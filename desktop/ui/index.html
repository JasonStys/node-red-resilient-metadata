Project & reliability policy

Saved project

Each item is sent to the original node as msg.payload. Invalid payloads intentionally produce structured validation failures.

Owned provider configuration

Documentation URLs remain text and are never fetched. Duplicate product/edition records, invalid record schema and oversized inputs are refused before saving. Metadata values keep your authored meaning and units; they are not automatically calibrated or converted.

Run evidence & history

Up to 10 runs / 16 MiB; older records are evicted explicitly.

Selected output / provider trace

Operational boundaries

  • The runtime's flow revision identifies its graph. The separate project SHA also binds messages, records and scenario.
  • Cancellation redeploys the actual flow and waits for node completion and provider response closure. A cancelled item is not reported as successful.
  • Workspace and exports are plaintext for one trusted OS account. They are not authenticated reviewers, encrypted storage or an unlimited archive.
  • Quit retains accepted operations and the actual child until normal completion. A stale owner lock is preserved for review after interruption.

Replace unsaved editor draft?

Keep editing to save first. Replacing changes only the editor; the current saved project and run history remain intact until an explicit save.
