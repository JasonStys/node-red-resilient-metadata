## Why a tracked source input

[npm supports tarball package specs](https://docs.npmjs.com/cli/v12/using-npm/package-spec/#tarballs), and [pnpm documents local and remote package sources](https://pnpm.io/package-sources). A verified supplemental public TAR was evaluated. Actual fresh pnpm 11.19.0 production updates refused its transitive HTTPS override with `ERR_PNPM_EXOTIC_SUBDEP`; adding the same direct dependency did not change that outcome. [pnpm's documented default](https://pnpm.io/settings#blockexoticsubdeps) permits direct exotic sources while refusing newly resolved transitive ones. That guard remains enabled by default; it was not disabled to make an update pass.

Tracking the small exact existing local input makes the required source available to the updater without a new registry, account, project hook or transitive URL exception. GitHub's [ecosystem support guidance](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories) explains that dependency sources must be available for resolution. The supplemental [tooling release](https://github.com/JasonStys/node-red-resilient-metadata/releases/tag/tooling-npm-12.2.2-workbench.1) remains a reproducibility source, not an application release or server-enforced immutable/signature claim.
