## Purpose and practical operation

The native workbench runs the original `metadata-service` and `resilient-metadata` nodes in genuine Node-RED 5.0.8. A developer can author message payloads, authorized provider records and bounded timeout, response, concurrency, queue and retry policies; save; deploy the real supported graph; and inspect outputs, original completion, request attempts and queue evidence. Prepared data is an editable scenario inside the same application.

The owner-local workspace opens automatically. There is no separate workspace chooser or New dialog. Use **Prepared project** or **Import project**, edit the closed-schema JSON and policy, then **Save project** and **Deploy and run**. A completed batch can contain failures. Change a fault scenario and compare real retry, malformed-response or held-request cancellation evidence. **Cancel active batch** redeploys the actual flow; cancelled/not-started work remains distinct from success.

Select a retained exact run to inspect or review its project before an explicit save/replay. **Keep editing** preserves an unsaved draft; **Replace draft** explicitly changes it. Export the saved project, an exact run or a credential-free ordinary Node-RED flow to a new selected file. That flow requires separately approved external integration configuration. Use **Exit application** and wait for accepted exports, the runtime child and owned provider to finish.

The [four-page illustrated guide](windows-application-guide-1.1.0.docx) contains two original installed screenshots and complete `desktop/flow-engine.cjs` lines 305–320, not a truncated return-only sample. Its [public paired manifest](windows-application-guide-1.1.0.json) binds the document, source-file, screenshot and individually reviewed page digests.

## Installation and operating limits

Download `NodeRedMetadata-1.1.0-windows-x64.zip` and its matching SHA256 sidecar from Releases. Verify the complete digest, extract the entire folder and launch `NodeRedMetadata.exe`; keep every runtime, resource and notice together. Use the individual icon or in-app Help. The application creates its workspace outside the program directory automatically.

Projects, records, current/previous saves, history and exports are plaintext trusted-OS-owner data. History is bounded to ten runs and 16 MiB, with explicit eviction. This is not authenticated multiuser approval, encryption, a full audit archive or a universal backup/migration guarantee. Static filesystem admission does not protect against a hostile concurrent writer running as the same account. Current/previous replacement is not a multi-file atomic transaction. Protect backups yourself and do not delete retained owner locks to force startup.

The native graph/provider are closed and owned-loopback only. Imports cannot choose arbitrary executable nodes, URLs, credentials or module paths; documentation URLs remain text. There is no external AI or live-machine connection. A recorded cancellation does not undo an external production side effect. The original installable node package remains available for separately configured approved services. These Windows x64 tests are not clean-machine or cross-platform installation certification; they opened no ordinary profile and did not change Docker.
